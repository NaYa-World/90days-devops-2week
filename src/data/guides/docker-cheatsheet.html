Dockerfile Instructions (100%)

InstructionDescription
FROM image:tagBase image (required, must be first)
WORKDIR /appSet working directory for subsequent instructions
COPY src destCopy files from host to image
ADD src destLike COPY but also extracts .tar and supports URLs
RUN commandExecute command during image build (creates layer)
CMD ["exec","param"]Default command when container starts (overridable)
ENTRYPOINT ["exec"]Command that always runs (not easily overridable)
EXPOSE 80Document which ports the container listens on
ENV KEY=VALUESet environment variable (available at runtime)
ARG KEY=VALUEBuild-time variable (only available during build)
VOLUME /dataCreate a mount point for external volumes
USER usernameSet the user to run subsequent commands as
LABEL key="value"Add metadata to the image
HEALTHCHECK CMD curl -f http://localhost/Define container health check command
SHELL ["/bin/bash","-c"]Override default shell for RUN commands
ONBUILD RUN ...Trigger instruction when image is used as base
STOPSIGNAL SIGTERMSet the system call signal for stopping
Dockerfile — Multi-stage Build
# Stage 1: Build
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: Production (smaller image)
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

Docker Networking

CommandDescription
docker network lsList all networks
docker network create <name>Create a new bridge network
docker network create --driver overlay <name>Create an overlay network (Swarm)
docker network inspect <name>Show network details (containers, IPs)
docker network connect <net> <cont>Connect a container to a network
docker network disconnect <net> <cont>Disconnect container from network
docker network rm <name>Remove a network
docker network pruneRemove all unused networks
docker run --network=host ...Use host's network stack directly
docker run --network=none ...No networking (fully isolated)
💡 Network Types

bridge (default) — containers on same host can talk. host — share host's network. overlay — cross-host communication (Swarm). none — no networking.

Volumes & Storage

CommandDescription
docker volume create <name>Create a named volume
docker volume lsList all volumes
docker volume inspect <name>Show volume details (mount point)
docker volume rm <name>Remove a volume
docker volume pruneRemove all unused volumes
docker run -v mydata:/app/data ...Named volume mount
docker run -v /host/path:/cont/path ...Bind mount (host directory)
docker run -v /cont/path ...Anonymous volume
docker run --tmpfs /tmp ...tmpfs mount (RAM, not persisted)
docker run -v data:/app:ro ...Read-only mount
💡 Volume Types

Named volumes — managed by Docker, persist after container deletion. Bind mounts — map host dir into container. tmpfs — in-memory only, fast but not persisted.

Troubleshooting

ErrorFix
permission denied on docker commandsAdd user to docker group: sudo usermod -aG docker $USER then re-login
port is already allocatedAnother process uses that port. Find it: lsof -i :8080 or change the host port
no space left on deviceRun docker system prune -a --volumes to reclaim disk
image not foundCheck image name/tag. Run docker pull image:tag first
container exits immediatelyCheck logs: docker logs <container>. Ensure CMD/ENTRYPOINT keeps process running
COPY failed: file not foundFile is outside build context. Check .dockerignore isn't excluding it
Cannot connect to Docker daemonStart Docker: sudo systemctl start docker or open Docker Desktop
Build cache too largedocker builder prune to clear build cache

Best Practices

📋 Docker Best Practices

• Use specific tags (node:18-alpine) not latest
• Use multi-stage builds to keep images small
• Use .dockerignore to exclude node_modules, .git, etc.
• Run as non-root user in production (USER node)
• Combine RUN commands with && to reduce layers
• Use COPY instead of ADD (unless you need tar extraction)
• Always add HEALTHCHECK for production containers
• Use named volumes over bind mounts for data persistence
• Clean up with docker system prune regularly
• Pin base image versions in CI/CD pipelines
