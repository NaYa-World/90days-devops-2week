Google Kubernetes Engine (GKE) Setup Guide

The complete, step-by-step guide to provisioning and managing Kubernetes on Google Cloud Platform (GCP).

What is GKE?

GKE is widely considered the gold standard of managed Kubernetes. Google invented Kubernetes, and their managed offering is extremely fast, highly automated, and seamlessly integrated with GCP.

Prerequisites

Before you begin, ensure you have the following:

  • gcloud CLI - The GCP command line tool.
  • kubectl - The Kubernetes command line tool.
  • An active GCP Project with billing enabled.
Install and Login 
# Authenticate
gcloud auth login

# Set your active project
gcloud config set project YOUR_PROJECT_ID

# Enable the GKE API
gcloud services enable container.googleapis.com
2

Create the GKE Cluster

Using the GCP Console

  1. Go to the GKE Console.
  2. Click Create.
  3. Choose Standard (gives you control over nodes) or Autopilot (Google manages nodes). For learning, Standard is better.
  4. Name your cluster.
  5. Under Node Pools, configure size to `e2-medium` (cost effective).
  6. Click Create. GKE provisions clusters extremely fast (~3-5 mins).

Using gcloud CLI (Standard Cluster)

We will create a standard GKE cluster with 2 worker nodes.

Terminal 
gcloud container clusters create my-gke-cluster     --region us-central1     --num-nodes 1     --machine-type e2-medium

Note: --num-nodes 1 with a regional cluster creates 1 node per zone (typically 3 zones = 3 nodes total).

3

Configure kubectl

Download the credentials to your local `~/.kube/config`.

Terminal 
gcloud container clusters get-credentials my-gke-cluster --region us-central1

Verify the connection:

Terminal 
kubectl get nodes
4

Deploy a Sample App

Terminal 
kubectl create deployment hello-server --image=us-docker.pkg.dev/google-samples/containers/gke/hello-app:1.0
kubectl expose deployment hello-server --type=LoadBalancer --port 80 --target-port 8080
Terminal 
kubectl get services

GCP provisions Network Load Balancers extremely fast.

📜 Day 1 Cheat Sheet

Cluster Management 
# List clusters
gcloud container clusters list

# Resize node pool
gcloud container clusters resize my-gke-cluster --node-pool default-pool --num-nodes 2 --region us-central1

Stop GKE & Clean Up

⚠ CRITICAL BILLING WARNING
GKE clusters cost money. The control plane is free for the first cluster per billing account, but you pay for the nodes and load balancers.

Destroy the Cluster

You cannot "pause" a GKE standard cluster completely. To stop paying, you must delete it or scale nodes to 0 (though you still pay for load balancers if you leave them).

Terminal 
gcloud container clusters delete my-gke-cluster --region us-central1

Day 2 (Advanced)

GKE-specific advanced concepts:

  • GKE Autopilot: Serverless Kubernetes. You don't manage nodes, you just pay per pod resource request.
  • VPC-Native Clusters: Pod IPs are natively routable within the GCP VPC.
  • Workload Identity: The secure way to allow GKE pods to access Google Cloud APIs (replaces exporting service account JSON keys).
