From running your first container to deploying complex multi-tier applications with Docker Compose.

What is Docker?

Docker is a platform designed to help developers build, share, and run modern applications. It packages software into standardized units called containers that have everything the software needs to run including libraries, system tools, code, and runtime.

L1

Beginner: Installation

Install Docker Packages and Start Docker Service on Ubuntu/Debian.

Ubuntu Terminal 
sudo apt update
sudo apt install -y docker.io
sudo systemctl start docker
sudo systemctl enable docker

Verify the installation:

Terminal 
sudo docker version
2

Deploy Nginx Container

Run your first container! We'll deploy an Nginx web server on port 8080.

Terminal 
docker run -d --name my-nginx -p 8080:80 nginx

-d: Detached mode (runs in background)
--name: Give the container a custom name
-p: Port mapping (HostPort:ContainerPort)

✓ Open your browser to http://localhost:8080 to see the Nginx welcome page!
3

Delete Docker Container

To remove a running container, you must first stop it, or force delete it.

Terminal 
# Stop the container
docker stop my-nginx

# Remove the container
docker rm my-nginx

# Or force remove it in one step
docker rm -f my-nginx
4

Copy Files to Container

You can copy files between your host machine and the container using docker cp.

Terminal 
# Create a custom HTML file
echo "Hello from Docker!" > index.html

# Copy it into the Nginx default html directory
docker cp index.html my-nginx:/usr/share/nginx/html/index.html

Intermediate: Pull Images

Images are the blueprints for containers. You pull them from Docker Hub.

Terminal 
# Pull an image without running it
docker pull ubuntu:20.04

# List all downloaded images
docker images
6

Write a Dockerfile

A Dockerfile is a script with instructions on how to build a custom image.

Dockerfile 
FROM node:18-alpine
WORKDIR /app
COPY package.json .
RUN npm install
COPY . .
EXPOSE 3000
CMD ["npm", "start"]
Build the Image 
docker build -t my-node-app:v1 .
7

Docker EXEC Operations

Need to run a command inside a running container? Use docker exec.

Terminal 
# Run a single command
docker exec my-nginx ls -la /usr/share/nginx/html

# Get an interactive bash shell inside the container
docker exec -it my-nginx /bin/bash
# (or /bin/sh if bash isn't installed)

Create Image from Container

If you made manual changes inside a container, you can save it as a new image. (Note: Using Dockerfiles is best practice, but commit is useful for debugging).

Terminal 
docker commit my-nginx my-custom-nginx:v1

Advanced: Networking

Create custom bridge networks so containers can communicate using DNS names.

Terminal 
# Create a network
docker network create my-app-net

# Run containers on the network
docker run -d --name db --network my-app-net postgres:13
docker run -d --name web --network my-app-net -e DB_HOST=db my-node-app:v1

Docker Volumes Mapping

Containers are ephemeral. Volumes persist data even if the container is deleted.

Terminal 
# Map a host directory to a container (Bind Mount)
docker run -d -v /path/on/host:/path/in/container nginx

# Use a Docker Managed Volume
docker volume create my-db-data
docker run -d -v my-db-data:/var/lib/postgresql/data postgres:13
11

Ports Mapping

Containers are isolated. To access a service running inside a container from the outside world, you must map a port on your host machine to a port inside the container.

Terminal 
# Map host port 8080 to container port 80
docker run -d -p 8080:80 nginx

# Map multiple ports
docker run -d -p 8080:80 -p 8443:443 nginx

# Bind to a specific IP address (e.g. localhost only)
docker run -d -p 127.0.0.1:8080:80 nginx
⚠ Note: The format is always -p HOST_PORT:CONTAINER_PORT. If you get a "bind: address already in use" error, it means another service on your machine is already using the HOST_PORT!

Save, Load & Transfer Images

Need to move an image to a server without internet? Save it as a tar file.

Terminal 
# Save image to a tar archive
docker save -o my-app.tar my-node-app:v1

# Load image from a tar archive on another machine
docker load -i my-app.tar

Write a Docker Compose File

Docker Compose allows you to define and run multi-container applications using YAML.

docker-compose.yml 
version: '3.8'
services:
  web:
    image: my-node-app:v1
    ports:
      - "8080:3000"
    depends_on:
      - redis
  redis:
    image: redis:alpine
    volumes:
      - redis-data:/data
volumes:
  redis-data:
Terminal 
docker-compose up -d

Pro: Troubleshoot Issues

Debugging crashing containers is a daily DevOps task.

Logs & Inspection 
# View logs (add -f to follow)
docker logs -f my-crashing-app

# Inspect container metadata (IP addresses, mounts, etc)
docker inspect my-nginx

# See real-time resource usage
docker stats
Resolving Dockerfile Issues (No Space Left)

If you run out of disk space while building, clean up dangling images and stopped containers:
docker system prune -a --volumes

Deploy Python/Node Apps

A pro DevOps engineer writes highly optimized Dockerfiles for language runtimes.

Python (FastAPI/Flask) Best Practice 
FROM python:3.9-slim
WORKDIR /app
# Install dependencies first (leverage layer caching)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
# Copy app code
COPY . .
CMD ["python", "app.py"]

Task 2: Multi-Stage Build for React/Node

Optimize image sizes by separating build tools from the final runtime.

  1. Stage 1 (Build): Use node:18. Copy package.json, run npm install, and run npm run build.
  2. Stage 2 (Runtime): Use nginx:alpine. Copy the built static files from Stage 1 into the Nginx html directory.
  3. Build the image. Check its size with docker images—it should be drastically smaller than the Node base image!
