Prometheus Basics

Prometheus is a time-series database that pulls metrics from targets via HTTP (usually /metrics).

ComponentDescription
Prometheus ServerScrapes and stores time-series data
ExportersExpose metrics (e.g., Node Exporter, Blackbox Exporter)
PushgatewayFor short-lived jobs to push metrics
AlertmanagerHandles alerts sent by Prometheus (silence, route, group)
💡 Metric Types

Counter: Always increases (e.g., total HTTP requests). Gauge: Can go up or down (e.g., memory usage). Histogram: Samples observations (e.g., request duration) into buckets. Summary: Similar to histogram but calculates quantiles.

PromQL (Prometheus Query Language)

Query ExampleDescription
http_requests_totalSimple query: all time series for this metric
http_requests_total{status="200"}Filter by label
http_requests_total{job=~"web.*"}Regex match on label
rate(http_requests_total[5m])Per-second rate of requests over last 5 minutes (Counter)
increase(http_requests_total[1h])Total increase in requests over last hour
sum(rate(http_requests_total[5m])) by (job)Sum the rates, grouped by 'job' label
node_memory_Active_bytes / 1024 / 1024Convert bytes to Megabytes (Gauge)
100 - (avg by (instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)Calculate CPU usage %
histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket[5m])) by (le))95th percentile request duration
up == 0Find instances that are down

Prometheus Alerting Rules

YAML — alert.rules.yml
groups:
- name: example
  rules:
  - alert: HighErrorRate
    expr: job:request_latency_seconds:mean5m{job="myjob"} > 0.5
    for: 10m
    labels:
      severity: page
    annotations:
      summary: "High request latency on {{ $labels.instance }}"

Grafana Dashboards

Grafana visualizes data from sources like Prometheus, CloudWatch, Loki, etc.

ConceptDescription
Data SourceWhere Grafana gets data (e.g., Prometheus URL)
PanelA single chart/graph (Time series, Stat, Gauge)
DashboardA collection of panels
VariablesDropdowns in dashboards to filter data (e.g., by instance or region)
💡 Import Dashboards

Don't build from scratch! Find community dashboards at grafana.com/dashboards. Popular IDs: 1860 (Node Exporter Full), 3119 (Kubernetes cluster monitoring).

Loki & Promtail (Lightweight Logging)

Grafana's log aggregation system. "Like Prometheus, but for logs."

ComponentDescription

Key Metrics to Track (The RED Method)

💡 USE Method (For Resources/Infrastructure)

Utilization (% time busy), Saturation (queue length), Errors.

💡 RED Method (For Services/Apps)

Rate (requests per second), Errors (failed requests), Duration (latency/response time).

ResourceWhat to Alert On
Node/VMCPU > 90%, Memory > 90%, Disk Space < 10% free, Load Average high
KubernetesPods CrashLoopBackOff, Node NotReady, High number of pending pods
DatabaseConnection pool exhaustion, Slow queries, Replication lag
Web ServiceHTTP 5xx rate > 1%, 99th percentile latency > 500ms
💡

Best Practices

📋 Alerting Best Practices

• Alert on symptoms (high latency) rather than causes (high CPU). Let the dashboard show the cause.
• Avoid alert fatigue. Every alert should be actionable. If you ignore it, delete it.
• Use routing. Send P1 alerts to PagerDuty/phone, send P3 alerts to a Slack channel.
• Include runbooks in alert descriptions ("Run this command to fix...").
• Monitor your monitoring stack (Meta-monitoring).
• Use labels effectively in Prometheus to allow slicing data in Grafana.
