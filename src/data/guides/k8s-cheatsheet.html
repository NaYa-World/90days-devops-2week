Services

CommandDescription
kubectl get svcList all services
kubectl describe svc <name>Service details (endpoints, ports)
kubectl expose deploy <name> --type=ClusterIP --port=80Internal-only service
kubectl expose deploy <name> --type=NodePort --port=80Expose on node's IP + random port
kubectl expose deploy <name> --type=LoadBalancer --port=80Cloud load balancer (AWS ALB/NLB)
kubectl get endpoints <svc>Show which pods back the service
kubectl delete svc <name>Delete a service
💡 Service Types

ClusterIP — internal only (default). NodePort — external via node port (30000-32767). LoadBalancer — cloud LB. ExternalName — DNS alias to external service.

Scaling (HPA, VPA, Resources)

CommandDescription
kubectl autoscale deploy <name> --min=2 --max=10 --cpu-percent=80Create HorizontalPodAutoscaler
kubectl get hpaList HPAs
kubectl describe hpa <name>HPA details (current/target metrics)
kubectl top nodesNode CPU/memory usage
kubectl top podsPod CPU/memory usage
kubectl set resources deploy/<name> -c=cont --limits=cpu=200m,memory=512MiSet resource limits
💡 Resource Units

CPU: 100m = 0.1 CPU core. 1 = 1 full core. Memory: 128Mi = 128 MiB. 1Gi = 1 GiB. Always set requests (guaranteed) and limits (max).

Health Probes

💡 Three Types

livenessProbe — Is the container alive? If failing, K8s restarts it.
readinessProbe — Is the container ready to receive traffic? If failing, removed from Service endpoints.
startupProbe — Has the container started? Protects slow-starting apps. Disables liveness/readiness until it passes.

YAML — All Three Probes
livenessProbe:
  httpGet:
    path: /healthz
    port: 8080
  initialDelaySeconds: 15
  periodSeconds: 10
readinessProbe:
  httpGet:
    path: /ready
    port: 8080
  initialDelaySeconds: 5
  periodSeconds: 5
startupProbe:
  httpGet:
    path: /healthz
    port: 8080
  failureThreshold: 30
  periodSeconds: 10

Troubleshooting

Status / ErrorCause & Fix
CrashLoopBackOffContainer keeps crashing. Check: kubectl logs <pod> --previous
ImagePullBackOffCan't pull image. Check image name/tag, registry auth, network
PendingNo node can schedule the pod. Check: resources, taints, PVC binding
ErrImagePullImage doesn't exist or private. Create imagePullSecrets
OOMKilledContainer exceeded memory limit. Increase limits.memory
CreateContainerConfigErrorMissing ConfigMap or Secret. Check kubectl get cm,secrets
Service not reachableCheck selector matches pod labels: kubectl get ep <svc>
Node NotReadyCheck kubelet: kubectl describe node <name>

Best Practices

📋 K8s Best Practices

• Always set resource requests & limits on containers
• Use namespaces to isolate environments (dev/staging/prod)
• Add health probes (liveness + readiness) to every deployment
• Use labels & selectors consistently for filtering
• Store config in ConfigMaps, secrets in Secrets (not in images!)
• Use kubectl apply (declarative) over create (imperative)
• Use HPA for auto-scaling based on CPU/memory
• Run kubectl diff -f file.yaml before applying changes
• Use kubectl explain instead of googling YAML fields
• Never run containers as root in production
