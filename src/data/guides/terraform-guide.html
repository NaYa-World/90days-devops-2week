What is Terraform?

📖 5 min read

Terraform is a free, open-source tool by HashiCorp that lets you define cloud infrastructure (servers, databases, networks) in simple text files. Instead of clicking around the AWS Console, you write a file that says "I want an EC2 instance" and Terraform creates it for you.

💡 Real-World Analogy

Imagine you're ordering food. The imperative way: "Go to the kitchen, boil water, add pasta, strain it, add sauce…" You describe every step. The declarative way (Terraform): "I want a plate of pasta bolognese." You describe what you want, and Terraform figures out how to make it happen.

📌 Why should you learn Terraform?
  • Reproducible: Run the same file 100 times → same infrastructure. No more "it works on my account."
  • Version Controlled: Store infrastructure in Git. Review changes in PRs before applying.
  • Automated: No more clicking through the AWS Console. One command creates everything.
  • Multi-Cloud: Works with AWS, Azure, GCP, Kubernetes, and 3000+ providers.
💡 Key Terms for Beginners

Provider = The cloud platform (AWS, Azure, GCP).
Resource = A thing you create (EC2, S3, VPC).
State = Terraform's memory — it remembers what it created.
HCL = HashiCorp Configuration Language — the simple language Terraform uses.

Installing Terraform

🔧 10 min

Before you can use Terraform, install it on your machine and configure AWS credentials.

Step 1: Install Terraform CLI
macOS (Homebrew)
brew tap hashicorp/tap
brew install hashicorp/tap/terraform
Ubuntu / Debian
sudo apt-get update && sudo apt-get install -y gnupg software-properties-common
wget -O- https://apt.releases.hashicorp.com/gpg | \
  gpg --dearmor | \
  sudo tee /usr/share/keyrings/hashicorp-archive-keyring.gpg > /dev/null
echo "deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] \
  https://apt.releases.hashicorp.com $(lsb_release -cs) main" | \
  sudo tee /etc/apt/sources.list.d/hashicorp.list
sudo apt-get update && sudo apt-get install terraform
Verify
terraform -version
Step 2: Configure AWS Credentials

Terraform needs your AWS Access Key to talk to AWS on your behalf.

Terminal
aws configure
# AWS Access Key ID:     YOUR_ACCESS_KEY
# AWS Secret Access Key: YOUR_SECRET_KEY
# Default region name:   us-east-1
# Default output format: json
⚠️ Security Warning

Never hardcode AWS keys in your Terraform files! Always use aws configure or environment variables. Terraform automatically picks up credentials from ~/.aws/credentials.

The Core Workflow

📖 5 min read
💡 Real-World Analogy

Building a house: terraform init = hiring the crew. terraform plan = reviewing the blueprint. terraform apply = building it. terraform destroy = demolishing it.

CommandWhat it does
terraform initDownloads the AWS provider plugin. Run once when you start a new project.
terraform planShows a preview of changes. Always run before apply!
terraform applyCreates/updates the infrastructure. Asks you to type yes.
terraform destroyDeletes everything Terraform created. Use with caution!
🚀 Your First Terraform Project (Step-by-Step)
Terminal
# Step 1: Create project folder
mkdir my-first-terraform && cd my-first-terraform

# Step 2: Create your first .tf file (we'll write content next)
touch main.tf

# Step 3: Initialize (downloads AWS provider)
terraform init

# Step 4: Preview changes
terraform plan

# Step 5: Create infrastructure (type 'yes')
terraform apply

# Step 6: Clean up to avoid AWS charges!
terraform destroy

HCL Syntax Deep Dive

📖 10 min read

Terraform files use HCL (HashiCorp Configuration Language). Every .tf file in your project directory is automatically loaded.

📌 Anatomy of a Terraform File
HCL — main.tf (fully annotated)
# ─── STEP 1: Tell Terraform WHICH cloud to use ─────────
provider "aws" {
  region = "us-east-1"   # AWS data center region
}

# ─── STEP 2: Define WHAT you want to create ─────────────
# Syntax: resource "PROVIDER_TYPE" "YOUR_LOCAL_NAME" { }
#   "aws_instance" = EC2 Instance (resource type)
#   "web_server"   = Name YOU choose (for referencing)
resource "aws_instance" "web_server" {
  ami           = "ami-0c55b159cbfafe1f0"   # OS template
  instance_type = "t2.micro"               # Size (Free Tier)

  # Tags = labels to identify in AWS Console
  tags = {
    Name        = "MyFirstTerraformEC2"
    Environment = "dev"
  }
}
📁 Common File Structure
FilePurpose
main.tfYour primary resources (EC2, VPC, S3, etc.)
variables.tfInput variables (like function parameters)
outputs.tfValues to display after apply (like server IP)
providers.tfProvider config (AWS region, version constraints)
backend.tfWhere to store state (S3, local, etc.)
terraform.tfvarsActual values for variables (like a .env file)

Variables & Outputs

📖 10 min read
💡 Real-World Analogy

Variables are like blanks in a Mad Libs game. You define the blank ("I want a server of size ____"), and fill it in later. Reuse the same config for dev/staging/prod by just changing variables.

📌 Defining Variables
HCL — variables.tf
variable "instance_type" {
  description = "The size of the EC2 instance"
  type        = string
  default     = "t2.micro"   # If no value provided, use this
}

variable "environment" {
  description = "Deployment environment (dev, staging, prod)"
  type        = string
  # No default — Terraform will ASK you for it
}
📌 Using Variables + Setting Values
HCL — main.tf
resource "aws_instance" "web" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = var.instance_type    # ← Use the variable!
  tags = {
    Name = "web-${var.environment}"   # ← String interpolation
  }
}
HCL — terraform.tfvars
# This file auto-loads when you run terraform apply
instance_type = "t3.small"
environment   = "dev"
📌 Defining Outputs

Outputs display useful info after terraform apply (like the public IP).

HCL — outputs.tf
output "server_public_ip" {
  description = "The public IP of the web server"
  value       = aws_instance.web.public_ip
}

What is Terraform State?

📖 5 min read
💡 Real-World Analogy

The state file is a shopping list with checkmarks. When you run terraform apply, Terraform checks each item. If it's already checked (exists in AWS), it skips it. New item? Creates it. Removed item? Deletes it from AWS.

After terraform apply, Terraform creates terraform.tfstate — a JSON file mapping your .tf config to real AWS resources. Without it, Terraform wouldn't know what it already created.

🚨 Never do these things

• Never delete the state file (resources become orphaned in AWS)
• Never edit it manually (use terraform state commands instead)
• Never commit terraform.tfstate to Git (it may contain secrets!)

Remote State (AWS S3)

🔧 15 min

By default, state is saved locally. In a team, everyone needs the same state. Store it in S3.

Step 1: Create the S3 bucket (one-time)
Terminal
aws s3api create-bucket \
  --bucket my-terraform-state-bucket-12345 \
  --region us-east-1
Step 2: Configure Terraform to use it
HCL — backend.tf
terraform {
  backend "s3" {
    bucket = "my-terraform-state-bucket-12345"
    key    = "project-name/terraform.tfstate"
    region = "us-east-1"
  }
}
✅ After adding a backend

Run terraform init again. Terraform detects the new backend and asks to migrate your local state to S3. Type yes.

State Locking (DynamoDB)

🔧 10 min
💡 Real-World Analogy

Two people editing the same Google Doc at once — changes conflict. State locking adds a "🔒 Editing…" banner. While one person runs terraform apply, nobody else can until they finish.

Step 1: Create the DynamoDB table
Terminal
aws dynamodb create-table \
  --table-name terraform-locks \
  --attribute-definitions AttributeName=LockID,AttributeType=S \
  --key-schema AttributeName=LockID,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST
Step 2: Add locking to your backend
HCL — backend.tf (complete)
terraform {
  backend "s3" {
    bucket         = "my-terraform-state-bucket-12345"
    key            = "project-name/terraform.tfstate"
    region         = "us-east-1"
    # State Locking — prevents concurrent applies
    dynamodb_table = "terraform-locks"
    encrypt        = true
  }
}

Modules (Reusable Code)

📖 10 min read
💡 Real-World Analogy

A module is like a Lego set with instructions. Build the first set (VPC module), then stamp out copies for dev, staging, and prod by calling it with different inputs.

Modules package a group of resources together so you can reuse them. No more copy-pasting 200 lines of VPC code.

HCL — main.tf
# Use a local module stored in ./modules/web-server/
module "web_cluster" {
  source        = "./modules/web-server"
  cluster_name  = "production"
  instance_type = "t3.medium"
  min_size      = 2
  max_size      = 10
}

# Or use modules from the Terraform Registry
module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "5.0.0"
  name    = "my-vpc"
  cidr    = "10.0.0.0/16"
}

Workspaces (Environments)

📖 5 min read

Workspaces let you manage dev, staging, prod using the same Terraform files. Each workspace gets its own isolated state.

Terminal
terraform workspace list        # List all (* = active)
terraform workspace new dev      # Create workspace
terraform workspace select prod  # Switch workspace
terraform workspace show         # Show current
📌 Using Workspaces in Code
HCL — main.tf
resource "aws_instance" "web" {
  ami           = "ami-0c55b159cbfafe1f0"
  # Bigger server in prod, smaller in dev
  instance_type = terraform.workspace == "prod" ? "t3.large" : "t2.micro"
  tags = {
    Name        = "web-${terraform.workspace}"
    Environment = terraform.workspace
  }
}
L1

Beginner: EC2 & Security Group

Your first Terraform project. Provision a web server and open port 80.

HCL — main.tf
provider "aws" {
  region = "us-east-1"
}

resource "aws_security_group" "web_sg" {
  name        = "allow_http"
  description = "Allow HTTP inbound traffic"
  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

resource "aws_instance" "web" {
  ami                    = "ami-0c55b159cbfafe1f0"
  instance_type          = "t2.micro"
  vpc_security_group_ids = [aws_security_group.web_sg.id]
  tags = { Name = "L1-WebServer" }
}

output "public_ip" {
  value = aws_instance.web.public_ip
}
✅ After apply

Run terraform output public_ip to get the IP. Don't forget terraform destroy when done!

L2

Intermediate: Custom VPC

Create the networking foundation for EKS/ECS — VPC, subnets, Internet Gateway, Route Tables.

HCL — network.tf
resource "aws_vpc" "main" {
  cidr_block           = "10.0.0.0/16"
  enable_dns_hostnames = true
  tags = { Name = "L2-VPC" }
}

resource "aws_subnet" "public_a" {
  vpc_id                  = aws_vpc.main.id
  cidr_block              = "10.0.1.0/24"
  map_public_ip_on_launch = true
  availability_zone       = "us-east-1a"
  tags = { Name = "public-subnet-a" }
}

resource "aws_subnet" "public_b" {
  vpc_id                  = aws_vpc.main.id
  cidr_block              = "10.0.2.0/24"
  map_public_ip_on_launch = true
  availability_zone       = "us-east-1b"
  tags = { Name = "public-subnet-b" }
}

resource "aws_internet_gateway" "igw" {
  vpc_id = aws_vpc.main.id
  tags = { Name = "L2-IGW" }
}

resource "aws_route_table" "public_rt" {
  vpc_id = aws_vpc.main.id
  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.igw.id
  }
}

resource "aws_route_table_association" "a" {
  subnet_id      = aws_subnet.public_a.id
  route_table_id = aws_route_table.public_rt.id
}

resource "aws_route_table_association" "b" {
  subnet_id      = aws_subnet.public_b.id
  route_table_id = aws_route_table.public_rt.id
}

Troubleshooting Guide

❌ Error: No valid credential sources found

Terraform can't find your AWS credentials.

Fix
aws configure
# Or export environment variables:
export AWS_ACCESS_KEY_ID="your-key"
export AWS_SECRET_ACCESS_KEY="your-secret"
export AWS_REGION="us-east-1"
# Verify:
aws sts get-caller-identity
❌ Error: Failed to load plugin / Provider not found

Provider plugin hasn't been downloaded.

Fix
terraform init
# If still failing, clear cache:
rm -rf .terraform .terraform.lock.hcl
terraform init
❌ Error: Error acquiring the state lock

Someone else is running terraform apply, or a previous run crashed.

Fix
# CAUTION: Only if you're SURE nobody else is running apply!
terraform force-unlock LOCK_ID
# The LOCK_ID is in the error message
❌ Error: Resource already exists

Resource exists in AWS but not in Terraform state.

Fix
terraform import aws_instance.web i-0abc123def456789
terraform plan   # Verify after importing
❌ Error: Backend config changed

You modified the backend block (e.g., changed the S3 bucket).

Fix
terraform init -reconfigure
# Or to migrate state to new backend:
terraform init -migrate-state
❌ terraform destroy is stuck

Some resources (RDS, EKS, NAT Gateways) take 10–20 minutes to delete.

Fix
# Target a specific resource
terraform destroy -target=aws_nat_gateway.main
# If Terraform is unresponsive: Ctrl+C, manually delete
# in AWS Console, then remove from state:
terraform state rm aws_nat_gateway.main
⚠️ Common Gotchas for Beginners

• Forgot terraform init — always run init in a new directory
• Wrong region — check you're looking at the right region in the Console
• AMI IDs are region-specific — an AMI from us-east-1 won't work in eu-west-1
• Free Tier — t2.micro is free for 750 hrs/month. t3.large costs money!
• Forgot terraform destroy — you WILL be charged for running resources
• State in Git — add *.tfstate and .terraform/ to .gitignore
