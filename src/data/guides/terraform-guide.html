Infrastructure as Code

Master HashiCorp Terraform. Automate your cloud infrastructure with declarative configuration, state management, and reusable modules.

1

What is Terraform?

Terraform is an open-source Infrastructure as Code (IaC) software tool that provides a consistent CLI workflow to manage hundreds of cloud services. It uses a declarative configuration language called HashiCorp Configuration Language (HCL).

Declarative vs Imperative: In an imperative approach (like bash scripts), you say how to do it ("create EC2, then attach SG"). In a declarative approach (Terraform), you declare what you want ("I want an EC2 with this SG attached"), and Terraform figures out the API calls and execution order to make reality match your declaration.
2

The Core Workflow

The standard Terraform workflow consists of three core commands:

  • terraform init: Initializes the working directory. Downloads required providers (like the AWS plugin).
  • terraform plan: Creates an execution plan. It shows you exactly what Terraform will do without actually doing it. (Always run this!).
  • terraform apply: Executes the actions proposed in a Terraform plan.
  • terraform destroy: Deletes all infrastructure managed by your configuration.
3

HCL Syntax & Connecting to AWS

A Terraform file typically ends in .tf. To provision infrastructure, you first declare a provider, and then you define resources.

hcl — main.tf
# 1. Define the Provider
provider "aws" {
  region = "us-east-1"
}

# 2. Define a Resource: BlockType "Provider_ResourceType" "LocalName"
resource "aws_instance" "web_server" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t2.micro"

  tags = {
    Name = "MyFirstTerraformEC2"
  }
}
4

Remote State (AWS S3)

Terraform keeps track of the real-world infrastructure in a file called terraform.tfstate. By default, it saves this locally. If you work on a team, you must store this file remotely so everyone shares the same source of truth.

hcl — backend.tf
terraform {
  backend "s3" {
    bucket         = "my-company-terraform-state-bucket"
    key            = "network/terraform.tfstate"
    region         = "us-east-1"
  }
}
5

State Locking (DynamoDB)

What happens if two DevOps engineers run terraform apply at the exact same time? The state file gets corrupted. To prevent this, we use a DynamoDB table to "lock" the state file.

hcl — backend.tf
terraform {
  backend "s3" {
    bucket         = "my-company-terraform-state-bucket"
    key            = "global/s3/terraform.tfstate"
    region         = "us-east-1"
    
    # Enable State Locking
    dynamodb_table = "terraform-locks"
    encrypt        = true
  }
}

Modules (DRY Code)

Modules are containers for multiple resources that are used together. They allow you to write reusable infrastructure code. If you need to spin up 5 identical VPCs, you write a VPC module once, and call it 5 times.

hcl — main.tf
# Calling a local module
module "web_cluster" {
  source        = "../modules/web-server-cluster"
  
  # Passing variables to the module
  cluster_name  = "production-cluster"
  instance_type = "t3.medium"
  min_size      = 2
  max_size      = 10
}
7

Workspaces (Environments)

Workspaces allow you to manage multiple environments (dev, staging, prod) using the exact same configuration files. Each workspace gets its own isolated state file in your S3 bucket.

  • terraform workspace new dev: Creates a new workspace.
  • terraform workspace select prod: Switches to the prod environment.
L1

Beginner: EC2 & Security Group

Your first Terraform project. Provision a web server and open port 80 to the internet.

main.tf 
provider "aws" {
  region = "us-east-1"
}

resource "aws_security_group" "web_sg" {
  name = "allow_http"
  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

resource "aws_instance" "web" {
  ami                    = "ami-0c55b159cbfafe1f0"
  instance_type          = "t2.micro"
  vpc_security_group_ids = [aws_security_group.web_sg.id]
}

Intermediate: Custom VPC Architecture

Provision the foundation for EKS or ECS. Create a VPC with 2 public subnets, an Internet Gateway, and Route Tables.

network.tf 
resource "aws_vpc" "main" {
  cidr_block           = "10.0.0.0/16"
  enable_dns_hostnames = true
}

resource "aws_subnet" "public" {
  vpc_id                  = aws_vpc.main.id
  cidr_block              = "10.0.1.0/24"
  map_public_ip_on_launch = true
  availability_zone       = "us-east-1a"
}

resource "aws_internet_gateway" "igw" {
  vpc_id = aws_vpc.main.id
}

resource "aws_route_table" "public_rt" {
  vpc_id = aws_vpc.main.id
  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.igw.id
  }
}

Advanced: S3 + CloudFront Static Site Module

Create a highly available, globally distributed static website using Terraform Modules.

  • Create a reusable module in a /modules/static-site directory.
  • Provision an S3 bucket configured for web hosting.
  • Provision an AWS CloudFront Distribution targeting the S3 bucket.
  • Configure Origin Access Control (OAC) so the bucket is private and only accessible via CloudFront.
  • Create a main.tf at the root that calls your module and passes the desired domain name as a variable.
