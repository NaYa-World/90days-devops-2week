💡 Fargate vs Managed Nodes

Use Fargate for serverless, bursty workloads where you don't want to manage OS patching. Use Managed Node Groups (EC2) for steady-state workloads, GPUs, or DaemonSets (Fargate does not support DaemonSets).

IAM Roles & IRSA

IRSA (IAM Roles for Service Accounts) lets you grant AWS permissions directly to a specific K8s Pod (e.g., allow Pod A to read S3) instead of granting it to the entire EC2 node.

Command / ActionDescription
eksctl utils associate-iam-oidc-provider --cluster=my-cluster --approveEnable OIDC provider (required for IRSA)
eksctl create iamserviceaccount --name my-sa --namespace default --cluster my-cluster --attach-policy-arn arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess --approveCreate IAM Role and K8s ServiceAccount linked together
kubectl describe configmap aws-auth -n kube-systemView the mapping of AWS IAM users/roles to K8s RBAC groups
⚠️ Pod Identity vs IRSA

AWS recently introduced EKS Pod Identity as a newer, simpler alternative to IRSA. It removes the need for OIDC providers, but IRSA is still widely used in existing clusters.

VPC & AWS Load Balancer Controller

By default, EKS uses the VPC CNI plugin, meaning every Pod gets a real IP address from your AWS VPC subnet.

Resource / AnnotationDescription
type: LoadBalancerCreates a Classic Load Balancer (Legacy)
service.beta.kubernetes.io/aws-load-balancer-type: "external"Creates a Network Load Balancer (NLB) via the AWS LBC (Modern approach for L4)
Ingress resourceCreates an Application Load Balancer (ALB) via the AWS LBC (Modern approach for L7 HTTP/HTTPS)
alb.ingress.kubernetes.io/scheme: internet-facingMakes the ALB public
alb.ingress.kubernetes.io/target-type: ipRoutes traffic directly to Pod IPs (bypasses NodePort). Highly recommended.

Storage (EBS & EFS)

DriverUse Case & Details
EBS CSI DriverBlock storage. Use for databases. ReadWriteOnce (can only attach to one node at a time). Must be in the same AZ as the pod.
EFS CSI DriverFile storage. Use for shared assets (e.g., WordPress uploads). ReadWriteMany (can attach to many pods across different AZs simultaneously).
💡 CSI Drivers Add-on

EBS is no longer built-in (in-tree) to EKS. You must install the EBS CSI Driver add-on for PersistentVolumes to work.

Scaling (Karpenter & Cluster Autoscaler)

HPA scales Pods. But when you run out of Node capacity, you need a Node Autoscaler.

ToolDescription
Cluster Autoscaler (CA)The legacy/standard way. Adjusts the desired size of an AWS Auto Scaling Group (ASG). Slow and rigid.
KarpenterThe modern, AWS-native way. Bypasses ASGs entirely. Provisions the exact right EC2 instance type (e.g., graviton, spot) just-in-time based on pending Pod requirements. Highly recommended for EKS.

EKS Troubleshooting

ErrorCause & Fix
error: You must be logged in to the server (Unauthorized)You aren't authenticated to AWS, or the IAM user/role you are using isn't in the aws-auth ConfigMap. Run aws sts get-caller-identity to check who you are.
Pods stuck in ContainerCreatingUsually a VPC CNI issue (no IP addresses left in subnet) or an IAM issue with the EBS CSI driver (can't attach volume). Check kubectl describe pod.
Load Balancer not provisioningAWS Load Balancer Controller is missing, or subnets lack required tags (kubernetes.io/role/elb = 1).
Node shows as NotReadyKubelet crashed, EC2 instance out of memory, or security group blocking API server communication.

EKS Best Practices

📋 Production Checklist

• Use Karpenter instead of Cluster Autoscaler for faster, more cost-efficient scaling.
• Use Spot Instances via Karpenter for non-critical workloads to save 70% on compute costs.
• Implement IRSA or Pod Identity. Never use IAM User Access Keys inside Pods.
• Use Private API Endpoints for security. Only allow access via a bastion host or VPN.
• Install the AWS Load Balancer Controller (do not rely on the legacy in-tree controller).
• Ensure subnets have enough IP addresses (VPC CNI consumes an IP per pod).
• Upgrade clusters incrementally (e.g., 1.28 → 1.29), don't skip versions.
